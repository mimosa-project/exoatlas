# ExoAtlas 要件定義書

## 1. 概要

ExoAtlas は、NASA Planetary Systems Dataset を用いて系外惑星データを探索・比較・可視化する Web アプリケーションである。

利用者は、発見年、発見手法、惑星半径、惑星質量、公転周期、恒星情報、位置情報などを切り口に、系外惑星の分布や観測バイアスを直感的に把握できる。

## 2. 目的

- NASA の系外惑星データを視覚的に探索できるアプリケーションを構築する。
- 発見手法や発見年代による傾向の違いを理解しやすくする。
- 惑星サイズ、質量、公転周期、恒星特性などの関係を比較できるようにする。
- 将来的な分析機能、機械学習、教育用途への拡張に耐える構成にする。

## 3. 対象ユーザー

- 系外惑星データを眺めながら理解したい学習者
- 天文学やデータ可視化に関心のある開発者
- 惑星候補を条件で絞り込みたい研究・教育用途の利用者
- Kaggle や NASA の公開データを使ったポートフォリオを作りたい利用者

## 4. スコープ

### 4.1 MVP スコープ

- CSV データの読み込み
- 惑星一覧の検索・フィルタリング
- 発見年ごとの発見数チャート
- 惑星半径と公転周期の散布図
- 全天上の位置分布表示
- 惑星詳細パネル
- FastAPI によるデータ API
- React によるフロントエンド UI

### 4.2 将来拡張スコープ

- ハビタブル候補スコア
- 太陽系惑星との比較
- 複数文献における測定値の比較
- データ更新ワークフロー
- ユーザーによるお気に入り保存
- PNG / CSV エクスポート
- 3D 星図表示

## 5. 利用データ

### 5.1 入力データ

- `dataset/NASA_Exoplanet_Composite.csv`
  - 主データとして利用する。
  - 惑星ごとに統合された代表値を扱う。

- `dataset/NASA_Exoplanet_Planetary.csv`
  - 将来拡張向けデータとして利用する。
  - 同一惑星に対する複数の文献値や測定値の比較に使う。

### 5.2 主な利用カラム

- 惑星基本情報
  - `pl_name`
  - `hostname`
  - `discoverymethod`
  - `disc_year`

- 惑星物理量
  - `pl_orbper`
  - `pl_orbsmax`
  - `pl_rade`
  - `pl_bmasse`
  - `pl_dens`
  - `pl_eqt`

- 恒星情報
  - `st_teff`
  - `st_rad`
  - `st_mass`
  - `st_spectype`

- 位置情報
  - `ra`
  - `dec`
  - `sy_dist`

## 6. システム構成

### 6.1 技術スタック

- バックエンド
  - Python
  - FastAPI
  - Pandas
  - Pydantic
  - uv

- フロントエンド
  - React
  - TypeScript
  - Vite
  - Plotly.js または Apache ECharts

- 開発補助
  - Ruff
  - pytest
  - ESLint
  - Vitest

### 6.2 構成方針

- バックエンドは CSV を読み込み、検索・集計済みデータを API として提供する。
- フロントエンドは API から取得したデータを可視化し、ユーザー操作に応じてフィルター条件を更新する。
- 初期段階ではローカル CSV をデータソースとする。
- 将来的に DB 化する場合でも、API 契約を維持して移行できる構成にする。

## 7. 機能要件

### 7.1 データ読み込み

- アプリケーション起動時に `NASA_Exoplanet_Composite.csv` を読み込む。
- 数値カラムは API レスポンスで数値として扱えるように変換する。
- 欠損値はフロントエンドで扱いやすいように `null` として返す。
- CSV が存在しない場合は、バックエンドで明確なエラーを返す。

### 7.2 惑星一覧

- 惑星の一覧をページング付きで取得できる。
- 惑星名、母星名、発見手法、発見年で検索・絞り込みできる。
- 半径、質量、公転周期、距離などで範囲フィルターできる。
- 一覧から惑星詳細を開ける。

### 7.3 発見タイムライン

- 年ごとの発見数を表示する。
- 発見手法別に積み上げ表示できる。
- 年範囲を指定して表示範囲を絞れる。
- チャート上の年を選択すると、惑星一覧のフィルターに反映できる。

### 7.4 惑星サイズ・軌道散布図

- 横軸に公転周期 `pl_orbper` を表示する。
- 縦軸に惑星半径 `pl_rade` または惑星質量 `pl_bmasse` を表示する。
- 対数軸表示に対応する。
- 点の色は発見手法で分類する。
- ホバー時に惑星名、母星名、発見年、半径、質量、公転周期を表示する。
- 点をクリックすると惑星詳細パネルを表示する。

### 7.5 天球マップ

- `ra` と `dec` を用いて惑星系の全天分布を表示する。
- 発見手法、発見年、距離で絞り込みできる。
- 観測領域の偏りが見える表現にする。

### 7.6 惑星詳細

- 惑星名、母星名、発見年、発見手法を表示する。
- 惑星半径、質量、密度、公転周期、軌道長半径、平衡温度を表示する。
- 恒星温度、恒星半径、恒星質量、距離を表示する。
- 欠損値は `Unknown` または空表示ではなく、UI 上で自然に未取得として扱う。

### 7.7 ハビタブル候補フィルター

- MVP では簡易条件による絞り込みとして実装する。
- 条件例:
  - 惑星半径が地球半径の 0.5 から 2.0 倍
  - 平衡温度が 180K から 320K
  - 公転周期または軌道長半径が取得済み
- 将来的にはスコアリング方式に拡張する。

## 8. API 要件

### 8.1 エンドポイント案

- `GET /health`
  - API の稼働確認

- `GET /api/planets`
  - 惑星一覧を取得
  - クエリ例:
    - `q`
    - `discovery_method`
    - `disc_year_min`
    - `disc_year_max`
    - `radius_min`
    - `radius_max`
    - `mass_min`
    - `mass_max`
    - `orbital_period_min`
    - `orbital_period_max`
    - `limit`
    - `offset`

- `GET /api/planets/{planet_name}`
  - 惑星詳細を取得

- `GET /api/discoveries/timeline`
  - 発見年ごとの集計を取得

- `GET /api/discovery-methods`
  - 発見手法の一覧と件数を取得

- `GET /api/scatter/orbit-radius`
  - 散布図用の軽量データを取得

- `GET /api/sky-map`
  - 天球マップ用の軽量データを取得

### 8.2 レスポンス方針

- JSON 形式で返却する。
- 欠損値は `null` とする。
- API はフロントエンドに不要な列を返さない。
- ページング可能な一覧 API は `items`, `total`, `limit`, `offset` を含む。

## 9. UI 要件

### 9.1 画面構成

- ダッシュボード画面
  - KPI
  - 発見タイムライン
  - 惑星サイズ・軌道散布図
  - 天球マップ
  - フィルターサイドバー

- 惑星一覧画面
  - テーブル
  - 検索ボックス
  - 条件フィルター
  - 詳細パネル

- 惑星詳細画面または詳細ドロワー
  - 惑星基本情報
  - 物理量
  - 恒星情報
  - 関連チャート

### 9.2 デザイン方針

- 宇宙らしさは出しつつ、データ分析ツールとして読みやすさを優先する。
- 暗色テーマを基本候補とするが、チャートの可読性を優先する。
- チャート操作、フィルター、詳細表示を同一画面内で完結させる。
- 大きな装飾よりも、密度のある情報表示を重視する。

## 10. 非機能要件

### 10.1 パフォーマンス

- 初期表示は 3 秒以内を目標とする。
- フロントエンドへ返す可視化データは必要な列に絞る。
- 大きな散布図ではサンプリングまたは WebGL 表示を検討する。
- CSV 読み込み結果はバックエンドでキャッシュする。

### 10.2 保守性

- API のレスポンス型は Pydantic モデルで定義する。
- データ変換処理は API ルーターから分離する。
- フロントエンドのチャートコンポーネントは再利用可能にする。
- uv により Python 依存関係を管理する。

### 10.3 テスト

- バックエンド
  - データ読み込みテスト
  - フィルター条件のテスト
  - API レスポンスのテスト

- フロントエンド
  - 主要コンポーネントの表示テスト
  - フィルター操作のテスト
  - API クライアントのテスト

### 10.4 エラーハンドリング

- CSV が存在しない場合は起動時または API 応答で明示する。
- 数値変換できない値は `null` として扱う。
- フロントエンドでは API エラー時に再試行可能な表示を行う。
